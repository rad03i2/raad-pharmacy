# 3.3.22.26 / versionCode 94

Scope: shopping gallery, list/card presentation, compact material count, quiet purchase feedback, bulk customer-area metadata.

CloudAuthGate previously invoked the app content from three distinct Compose callsites (authenticated, initializing with a cached session, refresh failure with a cached session). Moving between these branches disposed the NavHost and ActivityResult registrations. The content now has one stable callsite for the same allowed-session policy; explicit sign-out, credential mapping, background workers, notification permission and PIN rules are unchanged. A physical device stack trace was not supplied; the regression tests target the identified composition teardown and Android picker result delivery.

Shopping uses Android's native/backported image-only photo picker where available, and ACTION_GET_CONTENT image providers on older phones. It never starts a generic document picker for this action. URI data is bounded/validated/compressed using the existing local photo pipeline. A pharmacy/owner-scoped atomic local composer draft preserves the name, quantity and pending URI across recreation; photos remain local. An invalid/expired provider URI displays an error and permits reselection. Gallery availability on older phones depends on installed image providers.

The list is the initial view. The optional adaptive card grid uses stable UUID keys, independently saved scroll positions, off-main-thread bounded image decoding and larger photos. Both views retain the existing one-second purchase gesture and 24-hour recovery behavior. Only a successful local purchase commit produces a low-volume system UI click; it does not request audio focus or use financial/notification sound playback.

Additional Settings exposes bulk area management. Empty areas persist in an independent catalog and use the existing metadata sync worker. Assigned area names from actual customer rows remain visible. Customer selection uses UUIDs (including duplicate names), supports filtered bulk selection and reviews moves from existing areas. One Room transaction reads each current customer and changes only area if its expected area still matches; recovery holds roll back the transaction. Portable backup events retain complete updated customers. Existing pending full customer writes stay full; otherwise the durable outbox carries an area-only field mask. The server PATCH sends only `area` and verifies the returned tenant/UUID/non-deleted row and value before the exact revision is acknowledged. Missing/deleted customers are retained for review without inserting financial records or blocking all unrelated uploads. Other financial upload/ACK behavior is unchanged.

The additive Supabase catalog has pharmacy-scoped SELECT RLS, guarded RPC writes and an idempotent name key. The v26 snapshot is a new RPC; v24/v25 response shapes are unchanged. No financial schema or customer ledger migration is introduced (Room remains v4); the separate metadata SQLite database upgrades v2 to v3.

Validation in progress: the PostgreSQL isolated fixtures pass v24/v25/v26 shopping, area RLS, concurrent idempotent creation and unchanged financial rows. The additive catalog migration is deployed as `20261019191741_customer_area_catalog.sql`; read-only checks for Raad/Ahmad/Fuad confirm the old item/supplier snapshots are unchanged and catalog access is correctly scoped. Security advisors match the pre-existing baseline (no new findings).

Android tests pass the actual gallery result after saved-state recreation on API26/API35, list/grid anchors, bulk selection and financial field preservation, offline/lost-response area retries, exact revision acknowledgements, recovery rollback and non-starvation of financial uploads. Two initial test-harness issues (API26 AutoCloseable and missing screenshot tag) were corrected; dialog screenshots are captured only on API28+, since Android's Compose test capture does not support older dialog windows. All behavioral assertions still run on API26. Final exact-head CI/lint/build and signed publisher are pending. No production customer-area assignments or test notifications are performed.
