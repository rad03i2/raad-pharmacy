# المرحلة 16 — Release Candidate & Final QA

الإصدار المرشح: **v2.6.0-rc1**

هدف هذه المرحلة هو تثبيت التطبيق قبل الإصدار المستقر وعدم إضافة مزايا وظيفية جديدة قد تغيّر سلوك البيانات.

## بوابة الجودة الآلية

لا يُعتبر الـAPK مرشحًا صالحًا إلا إذا نجحت جميع الخطوات التالية في GitHub Actions:

1. اختبارات Unit للمحاسبة وقواعد الرصيد.
2. اختبارات Backup validation والتوافق.
3. اختبارات Room / SQLite والاستعلامات المجمعة.
4. اختبارات Compose الحالية.
5. فحص `lintRelease`.
6. بناء `assembleRelease` مع R8 وResource Shrinking.
7. إنشاء SHA-256 للـAPK ورفعه مع ملف البناء.

## اختبارات RC المضافة

### النسخ الاحتياطي والاستعادة

- Round-trip كامل: تصدير ثم قراءة النسخة مع الحفاظ على الحقول والحركات.
- رفض Backup من Schema أحدث بدل محاولة تفسيره بشكل قد يفسد البيانات.
- استمرار قبول صيغة النسخ القديمة المستخدمة قبل التنسيق الحديث.
- تجربة ملف واقعي أكبر: 200 زبون و400 حركة دون فقد سجلات.
- التأكد أن `replaceAll` Transaction ذرّية: إذا فشلت الاستعادة في منتصفها، تبقى البيانات الأصلية ولا تُمسح.

### قاعدة البيانات والحجم

- اختبار 250 حسابًا و500 حركة.
- التحقق من إجمالي الدين وعدد الحسابات المفتوحة.
- التحقق من إجمالي الديون والتحصيلات وعدد القناني عبر SQL aggregation.

## قائمة فحص ميدانية قبل النسخة المستقرة

هذه النقاط تحتاج جهاز Android فعلي لأنها لا يمكن إثباتها بالكامل من CI:

- تثبيت RC فوق نسخة قديمة تحتوي بيانات حقيقية والتأكد أن البيانات بقيت.
- تشغيل التطبيق من إغلاق كامل ومراجعة Splash والأيقونة.
- إضافة زبون بدين سابق.
- إضافة دين بالقناني وبمبلغ مباشر.
- تحصيل جزئي ثم تحصيل كامل.
- محاولة تحصيل أكبر من الرصيد والتأكد من المنع.
- تعديل وحذف حركة واختبار الحماية المحاسبية.
- تصدير Backup ثم استعادته.
- فتح كشف الحساب ومشاركته.
- تجربة إخفاء المبالغ وقفل التطبيق.
- اختبار التذكيرات بعد منح/رفض صلاحية الإشعارات.
- استخدام التطبيق مع لوحة المفاتيح مفتوحة وعلى شاشة صغيرة.
- إغلاق التطبيق أثناء الاستخدام ثم فتحه والتأكد من بقاء البيانات.
- اختبار البحث والمناطق والتقارير بعد إنشاء عدد كبير من الحركات.

## قرار الإصدار

إذا نجحت بوابة CI وتمت قائمة الفحص الميدانية دون مشكلة حرجة، يمكن تحويل النسخة من:

`2.6.0-rc1`

إلى الإصدار المستقر:

`2.6.0`

من دون تغيير Schema قاعدة البيانات.
