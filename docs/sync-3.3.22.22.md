# إصلاح رفض المزامنة HTTP400 — 3.3.22.22 (90)

## السبب المثبت

صورة الإصدار89 تعرض149 عملية محفوظة وإعادة محاولة مع HTTP400. فُحصت سجلات Supabase قراءةً فقط للفترة17 أكتوبر2026 من11:30 إلى15:20UTC: ظهر476 رفضًا برسالة `immutable customer identity fields cannot be changed`، ورمزSQLSTATE `P0001`، من `raad_private.protect_sync_identity_fields`. يبين نص الطلب محاولة UPSERT لحقول بينها `created_at`.

قارئ أندرويد يحول التاريخ إلى ميلي ثانية، بينما155من155 تاريخ إنشاء زبون و160من160 تاريخ حركة على الخادم تحتوي أجزاء أصغر من الميلي ثانية. إعادة إرسال الوقت المحلي المقرب في UPDATE تغير تاريخ الإنشاء الفعلي المحمي. كذلك تحمل الحركة محليًا وقت وقوعها، ولا تخزن وقت إنشائها السحابي المنفصل. إعادة محاولة UPSERT نفسه تعيد الرفض؛ ليست المشكلة انقطاع الإنترنت. لا تُضعف حماية الهوية لحلها.

## التنفيذ

- يستخدم الرفع المعتاد PATCH للحقول القابلة للتعديل فقط، مقيدًا بمعرّف السجل والصيدلية وحالة عدم الحذف، ومعرّف الزبون للحركة. لا يرسل `created_at` أو معرّفات الهوية أو المؤلف الأصلي في PATCH.
- عند عدم وجود سجل قابل للتعديل، ينفذ INSERT بهويته وتواريخه الأصلية. تعارض الإنشاء المتزامن409 يعيد محاولة التعديل الآمن؛ لا يُنشئ هوية بديلة، ولا يحيي سجلًا محذوفًا، ولا ينقل حركة إلى زبون آخر.
- يطلب ردًا يتضمن السجل المحفوظ ويفحص القيم المالية والهوية قبل رجوع الرفع بنجاح. يستمر إقرار outbox بواسطة المفتاح والمراجعة المحددين؛ الفشل أو رد مختلف أو انقطاع الاتصال يبقيان المحتوى الأصلي في الطابور.
- تهيئة الجهاز الأولية تستخدم INSERT مع تحقق عند سباق الإنشاء؛ لا UPSERT يعيد كتابة تاريخ السجل أو بيانات مالية أنشأها جهاز آخر.
- نجاح تفريغ الطابور يمسح تشخيص فشل الدفتر القديم وحده. لا يخفي إخفاقات الدخول أو الخدمات الأخرى.
- لا ترحيل لقواعد البيانات ولا تعديل لمشغلات الإنتاج أو RLS أو الأموال أو طابور المستخدم أثناء التطوير. استرداد21 وحماياته يظلان قائمين. لا تغيير للواجهة الرئيسية أو تسجيل الدخول أو التنبيهات أو PDF/تيليجرام.

## التحقق وحدوده

توجد إعادة إنتاج لرفض400 القديم عبر عميل Supabase/CIO الفعلي وHTTP محلي يحمي حقول الهوية، واختبارات لاستمرار التعديل بطلب واحد مع حفظ توقيت الخادم الدقيق، والمؤلف وهوية العملية والزبون، وطابور149 عملية، وانقطاع الشبكة وفقد رد الإدراج، والحذف وهوية الزبون المتعارضة، وسباق التهيئة، ورد200 ذي قيم مختلفة لا يجوز إقراره. يختبر PostgreSQL17 المعزول مشغل حماية مماثلًا ويثبت رفض UPSERT القديم ونجاح UPDATE للحقول المسموحة.

لم تُسحب نسخة طابور الهاتف الفعلية ولم تُنفذ كتابة مالية تجريبية على الإنتاج. لذلك تثبت الاختبارات معالجة سبب الرفض المشاهد، ولا تثبت رفع149 عملية بعينها قبل تثبيت الإصدار الجديد واتصاله بالخادم. تُحفظ الحالات الأخرى إن ظهرت، ولا تُحذف لإظهار نجاح ظاهري.
